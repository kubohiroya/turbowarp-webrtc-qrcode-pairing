TurboWarp-WebRTC-QRCode-Pairing

A TurboWarp extension that pairs WebRTC peers by carrying the offer and the answer optically, as QR codes.

How the workflow runs

  1. The integration machine creates an offer and cycles its QR codes on the projection.
  2. A camera machine reads the codes in any order until it has them all, accepts the offer, and shows the answer QR codes on its screen.
  3. An operator photographs every answer code with a smartphone and carries the images back.
  4. The integration machine scans those images, accepts the answer, and reports the connection.

No signaling server and no app on the smartphone: showing the photographed image is enough.

Before you start

  • Load turbowarp-webrtc, turbowarp-jsqr 0.4.0 or later and turbowarp-camera-source first.
  • Run the extension unsandboxed.
  • Turn on the pairing blocks at startup with globalThis.__TWQP_FEATURE_FLAGS__ = {qrCodePairing: true};

A projected pairing code is visible to everyone who can see the projection. The QR hash detects damage; it does not authenticate the other machine.

Fixed input editing

With a compatible TurboWarp GUI, enable fixed-input forms to edit only standard literal fields. Numbers use complete finite JSON number tokens; menu fields use existing choices. Connected reporters and unavailable fields stay read-only and are never evaluated. Saving an unchanged form preserves exact existing raw values, including legacy spellings and unknown choices. Invalid drafts stay in the same editing session; cancel, project/target replacement, or block removal discards them. Disabling the GUI feature flag restores native field editing. This form does not run blocks, open network/audio/key/QR sessions, resolve names, or edit Schema arguments. QR index is a positive integer without a session-derived candidate limit. Timeout remains 1–3600 seconds.
